## ★ 三类改动，生效方式完全不同

**混在一起时症状几乎一样**，这是最浪费时间的地方：

| 改动 | 生效方式 |
|---|---|
| `packages/client/src/boot.js` | **手机刷新页面**即可（每次请求都从磁盘读，且 `no-store`） |
| `packages/host/src/*`（新路由、改 HTML…） | ★ **退出并重开 DeepSeek Harness**（2026-10-04 更正 ✓：桌面端**已完全插件化** ✓ —— 重启就是「关掉 App 再打开」✓。**不要**再跑 `bash scripts/restart-lan.sh` ✗：那是插件化**之前**的「前台 CLI 形态」启动器 ✓，今天跑它会**又起一个 DSH** 并撞端口 ✗。★ 我（agent）就因为这条旧命令误导过用户一次 ✓）|
| `native/android/*` | `build-apk.mjs` → **手机覆盖安装 APK** |

### 验收结果怎么读（★ 最容易误判的一处）

- `check-mobile-layout` **以 `✓` 行数为准**，文档里写的条数就是这个数。
- 它有**硬超时** `HARD_TIMEOUT_MS = Number(process.env['ML_TIMEOUT_MS'] ?? 1_500_000)`
  （★ **2026-10-08 订正**：旧文写「当前 420 秒」✗ —— ★ 那已经过时两轮了：420 → 480（round 152 加真隧道一节）
  → 现在的默认值是 **1,500,000 ms = 25 分钟** ✓。
  ★★ **判据：要看脚本里当下的值** ✗，别照这里的数字推 ✗ ——
  我（agent）就因为照旧数字推，误判「它 ~7 分钟会被杀」✗，而它跑到 7:24 还活着 ✓。）超时 `exit=2` ——
  **断言可能全绿但脚本被强杀**，别误读成"有失败"。
- 环境类失败（`EADDRINUSE` / 连错实例 / 超时）**不是产品 bug**，等 60–120 秒重跑。

## ★★ 流程 v2（2026-09-27 定稿，"以后每轮照它走"）

> 凡某轮"**等待时间 > 改动时间**"，即视为流程违规。

### 1. 分派判据（"谁做"）

- **主线自己做**：≤1 小时、需要"看一眼效果再调"（样式 / 文案 / 小交互）、单文件小改
- **派子智能体**：需要多轮自动化验证、跨多文件、或必须长时间跑套件 / 重复验证
- **绝不派**：**美学/视觉验收**、只有一两行 CSS 的活、需要用户反复看效果的

### 2. 派单前（"要不要先问"）

- 外观 / 交互 / 取舍 / 多义句 ⇒ **先问用户一句**（"一句话 + 一两个选项"）
- 纯 bug 修复 / 明确的功能补全 ⇒ 直接做，但**用户原话原样引用进派单**
- ★ **读需求优先按字面**（"做一个控件" = **做**一个，不是"改一个已有的"）
- 不确定的地方**先问用户**，**不许让子智能体替用户猜需求**

### 3. 验收分级（"跑什么"）★

| 改动类型 | 自动验收怎么跑 |
|---|---|
| **美学 / 观感**（颜色、粗细、间距、节奏、动画好不好看） | **不跑** —— 用户看一眼说了算 |
| **可判定几何**（对齐 ≤Npx、不重叠、不被裁剪、不许闪、条数下界、存在性） | **定向断言**；只有涉及**布局引擎 / 多视口 / 全局 CSS** 才跑全量 |
| **协议 / 权限 / 宿主 / 安全** | **全量 + 变异**（变异**只跑受影响那一组**，最后再跑一次全量） |
| 纯文案 / 样式分支 | 定向断言 + 单测 |

**为什么"几何要跑、美学不跑"**：`check-mobile-layout.mjs` 头注释记着两次真实回归 ——
`[class*="collapsed"]` 选择器过宽导致网格轨道失效、区间替换误删 `grid-area` 三条规则，
**两次都通过了所有单元测试**。所以布局必须上真浏览器量；但**别把审美判断也塞进断言**。

### 4. 并行与构建（"别互相踩"）

- **一单独占它要改的文件**（并行前先按文件分配）
- ★ **`npm run build` / `install-host-plugin.mjs` / `restart-lan.sh` 只由主线在收工时做** ——
  **子智能体一律禁止**：`npm run build` 会顺带编译**别人正在改的 TS** ⇒ `lib/` 变成**混合快照**
- **端口**：套件改用系统临时端口；在此之前用 `ML_DSH_PORT` / `ML_PROXY_PORT` / `ML_TLS_PORT` 人工错开
- 环境类失败 ⇒ 等 60–120 秒重跑，**不许据此改产品代码**

### 5. 交付 —— ★ 固定给一张**验收卡**

```
【验收卡】
① 你要做什么：刷新页面 / 重启 DSH（终端）/ 装新 APK        ← 三选一或多选
② 点哪里、看什么（3–5 条，带期望）：
   · … → 应看到 …
③ 不对时给我什么：截图（连哪里）+ 调试框里哪几行
④ 本轮没验的：…（如实写，例如"观感由你判断"）
```

- 真机才现形的问题：**必须**在调试框留一行**可念**的日志，并在验收卡里点明**去哪看哪一行**
- **部署只由主线做**；子智能体交单时必须明确写"**部署动作未做**"

### 6. 归档与提交（"别丢线索"）

- 每轮结束**必须**更新 `10-交接文档.md`（§4.1x / §六 / §下一步）**并立刻提交**（代码仓 + 文档仓）
- **一单交单 = 一次提交**；并行时只提交**已完成那单**涉及的文件，WIP 留在工作区并**在回复里说明**
- ★ **文档滞后会变成别人的错误结论**（评估文档 14 就被过期的 §4.1l C 误导过）⇒ 宁可写"进行中"，**不许留旧结论**

### 7. 效率硬指标

- `check-mobile-layout` **耗时**：★ 2026-10-08 实测 ★ 跑到 **7:24 仍在跑** ✓（★ 与本机负载有关 ✓）；
  ★ 旧文写的「>900 秒 ⇒ 提速排卡（目标 ≤400 秒）」✗ 与「硬超时 420 秒」✗ **都过期** ✓ ⇒
  ★ 这条债**仍然成立**（套件偏慢 ✓），但**数字以当场实测为准** ✗
- 变异**按组**跑，最后再全量
- 每轮结束时自问：**"这一轮的等待时间有没有超过改动时间？"**

## rounds 归档：写到哪儿

改动按四类记（A 真正的产品能力 / B 修掉自己引入的缺陷 / C 纯弯路 / D ★ 最具长期价值——**"以后不会再这样"**）。

| 类 | 含义 |
|---|---|
| **A** | 真正的产品能力（必要，且长期有效） |
| **B** | 修掉自己引入的缺陷（该修，但本不该存在） |
| **C** | 纯弯路（花了时间没产生价值，但留下了教训） |
| **D** | ★ 最具长期价值 —— **不是功能，是"以后不会再这样"** |

## 浏览器层是怎么驱动的（手写 CDP，不是 Playwright）

```js
const CHROME = '/Applications/Google Chrome.app/Contents/MacOS/Google Chrome'
spawn(CHROME, ['--headless=new', `--remote-debugging-port=${cdpPort}`,
               `--user-data-dir=${chromeDir}`, '--no-first-run', '--disable-gpu',
               '--ignore-certificate-errors', 'about:blank'],
      { stdio: 'ignore', detached: true })
const ws = new WebSocket(target.webSocketDebuggerUrl)          // 直接说 CDP
await send('Emulation.setUserAgentOverride', { userAgent: '...Pixel 8...' })
```

**改这些脚本时注意**：

- 用 `mkdtempSync(join(tmpdir(), '<前缀>-'))` 建**独立** profile 目录
- 回收**只按自己的 profile**：`pkill -f --user-data-dir=<自己的临时目录>`
- **绝不按端口或按名字杀** —— 会误伤用户正常开着的 Chrome
- 这些脚本要起 DSH + 代理 + Chrome 三个进程，**任何一步卡住都会一直挂着**，所以每个早退点都要能走到清理逻辑（把清理放在最前面的 `finally`）

**Python 里 ⇒ 我自己那段编辑脚本语法错 ⇒ 整段改动根本没落盘** ✓（最难发现的一种 ✓）。

· Java 有机器守卫 ✓：`node scripts/check-java-quotes.mjs`（判据：**一个双引号两侧都是中文/全角标点** ✓，
  带 5 条自检样例 ✓；★ 试过扩到 `.py`/`.mjs` 又撤回了 ✗ —— 扩完报 228 处、绝大多数合法 ✓
  ⇒ **会误报的守卫等于没有守卫** ✓）。
· **其他语言没有守卫** ✗（Python 的 heredoc 更是内存里的东西、扫不到 ✓）⇒ 只能靠这条铁律 ✓：
  **凡是我写的中文句子，里面一律用「」** ✓。

## ★ 五条硬纪律（每条都是血换的）

1. **`boot.js` 只允许精确字符串替换**（禁下标切片 / 按注释整段替换——已两次造成 685/754 行死区）。
   每改完**必跑** `grep -o "^  function [A-Za-z0-9_]*(" packages/client/src/boot.js | sort | uniq -d`
   ⇒ **必须无输出**（同名函数后者胜出，症状只有"改了完全不生效"却全绿，两次死区唯一抓住它的就是这条）。
2. **验收断言只许加、不许松**：`EXPECTED_MIN_CHECKS` 只能**上调**；
   新行为必须做**变异验证**（把实现临时回退 ⇒ **恰好**新增那几条红、其余全绿 ⇒ 恢复后全绿）。
3. **构建 ≠ 部署**：`npm run build` 只写 `packages/*/lib`；**只有 `install-host-plugin.mjs` 才把
   `boot.js` / APK 装进 profile**（"验收全绿、手机上还是旧的"就是这么来的）。
   重启 DSH = **退出并重开 DeepSeek Harness**（★ 2026-10-04 更正：旧文档写的 `scripts/restart-lan.sh` 是插件化之前的 CLI 启动器 ✗，别再用它）。
4. **两单不许同时改同一个文件**（`boot.js` / `packages/host/src/index.ts` 这类必须一个 agent 独占）；
   成规模的实现/排查**派子智能体**，主线只做分派、复核与文档汇整。
   ⚠️ 但**子智能体禁止跑 `npm run build` / `install-host-plugin.mjs`**，也**禁止自己重启 DSH**（见流程 v2 第 4 条）。
5. **`devices.json` 改完必须立刻重启**（`DeviceStore` 只在构造时 `load()` 一次、之后整张内存表覆盖写文件），
   否则删掉的条目会被下一次 `touch()` 原样写回；用 `scripts/clean-devices.mjs` + 立刻重启。
